# Конвейер разработки агентами

Как я веду разработку с ИИ-агентами. Продукт собирает спеку, планировщик режет её на тикеты
с критериями приёмки, оркестратор запускает воркеров и верификаторов, мержит и двигает доску.
Приёмка результата остаётся за мной.

Карта конвейера: [index.html](index.html). Страница самодостаточная, диаграммы рисует Mermaid.

Это описание метода. Названия продукта, имена папок и данные заказчика здесь заменены
на нейтральные или убраны.

## Роли

Семь ролей, у каждой своя модель, своя папка и свой набор прав. Воркер, верификатор и куратор
со мной не разговаривают: их открывает оркестратор, результат они сдают файлом.

| Роль | Что делает | Кто запускает |
|---|---|---|
| Продукт | Отвечает на вопросы файлами, правит спеку и решения, ведёт глоссарий. Код не трогает | я или оркестратор |
| Планировщик | Режет спеку на тикеты с критериями приёмки и границами | я |
| Оркестратор | Ведёт волну: открывает воркеров и верификаторов, мержит, пушит, двигает доску. Код не читает | я, один раз на волну |
| Воркер | Один тикет, одна ветка, одно воркдерево. Сдаёт хендофф со статусом и выходит | оркестратор |
| Верификатор | Адверсариальная проверка: свежая сессия, другая модель, вердикт только с доказательствами | оркестратор |
| Куратор | Ретро раз в 5–10 тикетов: грабли, хуки, тесты, чистка правил | оркестратор |
| Архитектор конвейера | Проектирует роли и правила вместе со мной. В разработке не участвует | я |

## Путь тикета

```
ready-for-agent → claimed → in-progress → review → verified → «Принято владельцем: дата» → done
```

Один тикет — одно воркдерево — одна свежая сессия. Чужой контекст не дотягивается: если сессия
упала, тикет продолжает новый воркер с того же хендоффа.

## Гейты, которые нельзя обойти

1. Критерии приёмки отмечены в тикете.
2. Быстрые тесты и guardrails зелёные, лог сохранён.
3. Ничего из списка «не трогать» не изменено.
4. Независимый вердикт верификатора `pass` с доказательствами.
5. Rebase на интеграционную ветку, повторный прогон тестов, мерж.
6. Приёмка владельца: строка «Принято владельцем» в тикете.
7. CI зелёный. В `main` только через PR.

Эти пути закрыты хуком и тестами, а не договорённостью: снять критерии приёмки, тронуть «не трогать»,
слить без вердикта, поставить `done` без строки владельца или запушить в `main` мимо PR нельзя.

## Эскалация

Сигнал, а не настроение. Поводом служат два `fail` верификатора, две неудачные попытки воркера,
красные тесты после петли исправлений, тикет с миграциями или решением об архитектуре.

По сигналу модель поднимается один раз до конца тикета: верхняя модель даёт диагноз и план,
исполняет средняя. Провалом роутинга считается эскалация по настроению, смена модели посреди
тикета из-за лимита и дотягивание чужого контекста.

## Пороги контекста

Считает харнес, а не агент. На 35% нужно закончить атомарный блок, обновить хендофф и закоммитить,
новое не начинать. На 45% — стоп, хендофф, коммит, выход. Тикет продолжает новый воркер.

## Роутинг моделей

Модель выбирается на сессию, а не на запрос: роли задают модель и профиль, конвейер режет работу
на сессии и каждой выдаёт свою. Верхние роли работают на Claude Code и Kimi Code, исполнение —
на кодинг-модели. Отдельная фаза «план» у воркера идёт на верхней модели, реализация — на дешёвой:
продолжения съедают основную часть токенов, и верхняя модель там не нужна.

## Состояние и правило

Состояние живёт в файлах репозитория: доска, тикеты, хендоффы, отчёты верификатора, вопросы
продукту, глоссарий, журнал грабель.

Правило конвейера: **если этого нет на диске, этого не было**. Доклад в чате не считается.
