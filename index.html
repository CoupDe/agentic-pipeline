Agentic Software Development Life Cycle / ASDLC

Так я веду разработку: агенты делают работу, человек отвечает за намерение и приёмку. Состояние процесса лежит в файлах репозитория: один тикет, одна рабочая копия, одна свежая сессия. Ниже эта схема в BPMN 2.0.

запрос → проверка окружения → выбор контура → работа → приёмка человеком

схема процесса, 37 элементов, 18 связей
· колесо — масштаб, перетаскивание — сдвиг

Читается слева направо. Ромб после проверки окружения разводит процесс по четырём контурам: основной путь вверху, ниже прогон проверок, восстановление и обновление базы знаний.

четыре контура
контурчто происходит
основной путь инициатива → эпик → Spec Package → архитектурный контракт → принятый спринт
agent evals сменились промпты или проверки: прогон до раскатки конфигурации
recovery / cutover сбой или переезд: путь восстановлен либо переключён
knowledge base накопились уроки: правила и политика обновлены

Роли на схеме: человек, продакт-агент, архитектор-агент, оркестратор, agent supervisor, куратор-агент. Артефакты шага — файлы: intent.md, spec.md, Constraint Register, Architecture Contract, ADR. Не на диске — значит, шага не было.
